## Follow-up pass (same session)

### Export determinism bug (real, fixed)
`test_byte_stability.py` was flaky ~1 run in 8. Root cause was two separate
wall-clock leaks, both violating exit criterion E4:
- **XLSX**: `_stabilize_xlsx_zip` pinned ZIP member dates but not file
  contents, and openpyxl writes `<dcterms:modified>` from the wall clock even
  after the caller sets `properties.modified`. Confirmed by byte-diffing
  `docProps/core.xml`: `2026-09-08T23:22:34Z` vs `...35Z`.
- **PPTX**: had no stabilization at all, so ZIP member timestamps were the
  wall clock. Different failure mode — identical entry contents, different
  member dates.

Fix: new shared `engines/export-engine/zip_stability.py` (`stabilize_zip`)
that pins member dates AND rewrites dcterms created/modified to
`2000-01-01T00:00:00Z`. `xlsx_format`, `pptx_format`, `docx_format` all
delegate to it. Verified 0 mismatches in 300 exports per format, and the
stability test passed 10/10 runs (was ~7/8).
The PyInstaller spec auto-discovers modules with `rglob("*.py")`, so the new
file needs no spec change.
